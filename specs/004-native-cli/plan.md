# Implementation Plan: A Native `flow` Binary, Released and Brewable

**Branch**: `004-native-cli` | **Date**: 2026-10-05 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/004-native-cli/spec.md`

## Summary

`flow` ships as one executable per platform, attached to every tagged release with a checksum and
installable from ankka's Homebrew tap. The build is ankka's: the same sbt plugin, GraalVM and four
runners (R1). What is different is what this CLI carries — a Kubernetes client, Jackson and a YAML
writer, all reaching things a native image cannot see at build time — so the image's reachability
configuration is generated by the tracing agent and pruned (R2), and the binary is held to the JVM
build by the CLI's own suite, run through a second driver that spawns it (R3), and by a smoke
script that diffs its output against the JVM build's on every sample (R4). The release gains a
release page, four legs and a formula job (R5); because the tap is shared, the formula is written
by commit and push, never by a force-pushed subtree, and ankka's job has to change the same way
first (R6). CI builds the Linux image on every change to the CLI (R8). The install page says
install; building from source moves to the contributing pages (R10).

## Technical Context

**Language/Version**: Scala 3 (the CLI; the build), Bash (the smoke script, the workflow steps),
Ruby (one Homebrew formula), YAML (two workflows)

**Primary Dependencies**: none added to the CLI. GraalVM 25 community (`native-image`) at build
time; sbt-native-packager's `GraalVMNativeImagePlugin`, already in `project/plugins.sbt`. `logback`
is removed from the CLI for `slf4j-nop` (R2; verify first)

**Storage**: none. Artifacts on the tag's GitHub release; one file in the tap

**Testing**: the existing `cli/test` suite (43 cases), unchanged in content, run twice — in process
and against the binary — through one driver seam; `cli/native-smoke.sh`; `ci.yml`'s `cli-native`
job on Linux; a pre-release tag for the release path

**Target Platform**: macOS arm64 and x64, Linux x64 and arm64, with no JVM

**Project Type**: build and release of an existing CLI; documentation

**Performance Goals**: the native `flow version` answers in well under a second; the suite against
the binary takes about as long as in process plus a process start per case

**Constraints**: `flow`'s behaviour, messages and exit codes unchanged; no case skipped for the
binary; `images`, `sdk-python` and `marketplace` never wait on the new jobs; the tap's `ankka.rb`
never touched by this repository; every `-Dflow.*` switch forwarded; warning-free compile

**Scale/Scope**: `build.sbt`, 1 properties file and a generated reachability set, `Main.scala` and
`Reset.scala` (the `resetter` parameter), `CliFixtures.scala` and `CliResetSuite.scala` (the
driver and the kubeconfig), 1 smoke script, 1 formula, `release.yml` (+3 jobs) and `ci.yml` (+1),
`Justfile` (+1 recipe), 5 docs pages changed and 1 added, 2 skills; one small pull request in
ankka

**Structure Decision**: no new module. The binary is a second packaging of `cli`; the tests are

## Order of work

1. The driver seam and the kubeconfig in the suite, in process only; green, and committed before
   any native work (quickstart tier 1).
2. The native build: plugin, properties, `slf4j-nop`, the agent run, the pruned configuration;
   the suite against the binary; the smoke script with the diff (tier 2).
3. CI's `cli-native` job.
4. The formula, the three release jobs, the pull request in ankka that stops its force-push.
5. The docs and skills (tier 3).
6. A pre-release tag, once ankka's change is merged and the secret is set (tier 4).

## Complexity Tracking

Nothing violates a rule. What is added, and why nothing simpler does:

| Addition | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| A second test driver | the only proof that the binary is the CLI is the suite (FR-005) | a smoke script alone enumerates; it cannot catch a reflection path a new command adds |
| A kubeconfig for the mock server, replacing an injected client | a binary cannot take a parameter (R3) | keeping the injection in process and skipping reset cases against the binary skips the reflection-heaviest path |
| Generated reachability configuration | fabric8, Jackson and YAML reach classes by name (R2) | hand-written entries break on the next fabric8 upgrade |
| A release page and three jobs | archives need somewhere to live; the formula needs the checksums (R5) | attaching to a release that does not exist fails |
| A change in ankka's release | its force-pushed subtree would erase this formula (R6) | a second tap, which the spec rules out |
| A CI job that builds the image | a broken image found at a tag is a half-published release (R8) | finding it at the tag |

## Constitution Check (post-design)

Re-evaluated after Phase 1: unchanged, all kept. The design adds no library to the build, no
module, no change to what `flow` does; it adds a build target, a test switch, a smoke script, a
formula and four workflow jobs.

Found while planning, and recorded in the spec's assumptions or the contracts:

- ankka-flow's release creates no GitHub release page; one is created for the tag.
- ankka's `homebrew` job force-pushes a subtree to the tap's `main`, which would remove this
  formula; ankka changes first (contracts/release-artifacts.md).
- A token with write to the tap is a secret outside the repository (`HOMEBREW_TAP_TOKEN`).
- `logback` leaves the CLI, for `slf4j-nop`; to verify that a user loses no message.

## Not in this feature

A native sidecar or operator; Windows; apt, dnf, winget; signing and notarisation; a JVM zip of
the CLI on the release (ankka attaches one; not asked for here); any change to what `flow` does.
